# Clipx code review — 2026-09-06

This codebase is worth repairing. It has useful foundations—versioned migrations, parameterized SQL, small stores, separate rendering backends, native media APIs, and tests—but several existing workflows can crash, lose metadata, or produce the wrong output. The evidence supports fixing those failures and clarifying ownership of persistent operations before deciding how much to restructure.

The review covers the entire current implementation at `6f50346ad396f27254884f766f9202e0d2705778`: **77 Swift source files, 22 test files, 15,121 Swift lines**, plus the build manifest, configuration, scripts, resources, and documentation. This is a full-tree review, not a review of the latest diff. The existing edit to `plans/ai-features.md` was preserved; that document explicitly describes future work, so its unimplemented features are not counted as defects.

No application source, existing tests, configuration, user library, or user footage was changed. This document is the only addition to the checkout. Builds and disposable reproductions used temporary copies and synthetic fixtures.

## Maintainability assessment

**Persistent operations have no single owner.** Saving a clip can mean inserting a range, then separately updating rating, purpose, and tags; undo reconstructs a different subset; the inspector writes other fields through raw SQL. Every caller also decides whether to publish `libraryRevision`. Adding a Clip field therefore requires finding every creation, restoration, and notification path. The incomplete Undo and stale search findings are concrete consequences. A complete clip mutation and restoration boundary would remove this repeated bookkeeping.

**Asynchronous work outlives the request that started it.** Player loading, library reloads, Light Table queries, project headers, session rails, browser search, and export cancellation each manage ownership differently. Several detached queries publish without checking whether their query/source/project is still current. The player crash is reproduced; stale-result races in the other views are source-supported risks. Captured request inputs, cancellation, and completion ownership need a consistent contract.

**Navigation state and query semantics are duplicated.** `selectedProjectID` and `selectedCollectionID` coexist with project/collection sets inside `activeFilters`; different entry points update different combinations. Sources, saved clips, calendar, Light Table, and web routes also compile different subsets of filters. This produces the project/collection intersection bug, ineffective date filters, and invisible calendar matches. One authoritative scope and explicit result semantics would make future search work much safer.

**Rendering rules are copied between entry points.** Menu export, drag materialization, and Stint rendering separately choose timing, transforms, speed, cancellation, and cleanup. Drag already omits edits that the other paths apply. The shared boundary should describe the complete render operation, while backends implement that operation for their platform.

**Directories provide organization, but not enforced module boundaries.** Xcode compiles the source directories into one application module. Core code reaches into `AppState.shared`; BookmarkStore returns a UI descriptor; many services reach through `AppEnvironment.shared`. This makes isolated lifecycle tests harder and permits unrelated features to depend on one another. Physical separation into many packages is not established as necessary; reducing these concrete dependencies would already help.

**Error handling often announces success without establishing it.** `FolderWatcher.add` catches bookmark errors internally, while ImportCoordinator immediately shows an “Added” toast. Several writes use `try?`, and failed indexing is indistinguishable from an unchanged file in rescan summaries. Conversely, database recovery treats every open failure as corruption. Errors need a meaningful result at the boundary that owns the operation, with failed writes preserving the user's draft or retryable work.

**The tests cover components better than workflows.** The suite contains useful database, tag, frame-math, and thumbnail checks. But keyboard tests inspect source strings, bootstrap tests avoid bootstrap, and some indexer tests repeat SQL instead of calling the indexer. Existing export/bridge tests do not verify rendered cut boundaries, full XML schema validity, or identity-preserving round trips. The isolated probes demonstrate that stronger tests are feasible without accessing the user's library.

## Storage, indexing, and build findings

**C01 · P1 — A temporary database-open failure can replace a healthy library.** [Database.swift:32](/Users/henry/Desktop/clipx/Sources/ClipxCore/Database/Database.swift:32) catches every opening, integrity-check, and migration error, moves the database aside, and restores an old backup or creates an empty library. An actual-method probe held an exclusive lock on a healthy temporary rollback-journal database; after `SQLITE_BUSY`, reopening succeeded with zero sources and the original file renamed “corrupt.” The original bytes remain available for manual recovery, but the active library has silently lost its current state. Recovery must distinguish corruption from locks, permissions, storage failures, and migration errors; those errors should not initiate replacement.

**C02 · P2 — An invalid backup defeats the advertised fresh-database fallback.** At [Database.swift:40](/Users/henry/Desktop/clipx/Sources/ClipxCore/Database/Database.swift:40), a backup is copied into the canonical path before validation. If opening it fails, the final `openMigrating` retries that same bad file. A probe with corrupt main and backup files consistently threw instead of creating the fallback. Validate a restore candidate separately and handle its failure explicitly before retrying the canonical path.

**C03 · P2 — Restored unchanged files remain offline.** [Indexer.swift:127](/Users/henry/Desktop/clipx/Sources/ClipxCore/Indexer/Indexer.swift:127) returns early when mtime and size match, without setting `online = 1`. A file marked offline after removal can return unchanged and remain excluded by availability filters, including after a rescan. An actual Indexer probe reproduced this. A live volume-mount notification repairs some cases, but a drive restored while the app is closed or an individually restored file still hits the shortcut. Availability needs reconciliation independently of content-change detection.

**C04 · P2 — Moved bookmarks resolve correctly but retain the obsolete stored folder path.** [BookmarkStore.swift:61](/Users/henry/Desktop/clipx/Sources/ClipxCore/Bookmarks/BookmarkStore.swift:61) resolves the moved URL, while [refreshBookmark at line 105](/Users/henry/Desktop/clipx/Sources/ClipxCore/Bookmarks/BookmarkStore.swift:105) updates by the new path, which does not match the old row. The actual probe moved a watched directory: resume returned the new URL, but `folders.path` remained the nonexistent old path. [FolderWatcher.rescanAll](/Users/henry/Desktop/clipx/Sources/ClipxCore/Watcher/FolderWatcher.swift:78) then uses that old path; access cleanup is also keyed inconsistently. Updating bookmark/path identity must keep folder records, source references, watcher roots, and active scopes coherent.

**C05 · P2 — The watcher ignores events that require reconciliation.** [FolderWatcher.swift:189](/Users/henry/Desktop/clipx/Sources/ClipxCore/Watcher/FolderWatcher.swift:189) skips all events without the individual-file bit and never handles `MustScanSubDirs` or dropped-event recovery. It still advances the persisted event ID. A dropped/coalesced notification can therefore leave the library stale until a later scan. `rescanAll` only indexes present files; missing-source reconciliation runs separately at bootstrap. This is a code-and-platform-contract finding, not a reproduced kernel-event overflow: [Apple requires rescanning after these flags](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/UsingtheFSEventsFramework/UsingtheFSEventsFramework.html). A scan should reconcile additions, changes, and removals as one operation.

**C06 · P2 — Automatic FTS repair misses the desynchronization it claims to repair.** [SearchEngine.swift:21](/Users/henry/Desktop/clipx/Sources/ClipxTagging/SearchEngine.swift:21) runs `integrity-check` without `rank = 1`. For this external-content FTS table, that checks internal index structure but not correspondence with the clips table. An actual-method probe emptied the index: `isIndexHealthy()` returned true, `verifyAndRepairIndex()` did nothing, and a known clip remained unsearchable. The existing test calls `rebuildIndex()` directly, bypassing the faulty detection. [SQLite documents the external-content check](https://www.sqlite.org/fts5.html#the_integrity_check_command).

**C07 · P2 — The Direct test scheme silently omits its two backend tests.** [project.yml:116](/Users/henry/Desktop/clipx/project.yml:116) does not set `DIRECT_BUILD` on the test target, while [ExportPresetTests.swift:31](/Users/henry/Desktop/clipx/Tests/ClipxCoreTests/ExportPresetTests.swift:31) places both ffmpeg tests behind that condition. The normal suite passes 116 tests rather than executing all 118 test methods. Enabling the condition only in the temporary test target ran both and exposed the stale seek assertion at line 48. The MAS scheme has no corresponding runtime test target. Build-variant coverage needs to be explicit; choosing the Direct scheme does not propagate its Swift conditions to tests.

**C08 · P1 for distribution — The build never bundles ffmpeg.** [project.yml:32](/Users/henry/Desktop/clipx/project.yml:32) includes Sources and Resources but has no helper copy phase. [setup.sh](/Users/henry/Desktop/clipx/Scripts/setup.sh:15) and [bundle-ffmpeg.sh](/Users/henry/Desktop/clipx/Scripts/bundle-ffmpeg.sh:22) put the binary in `Helpers/`, which the build does not consume; the actual built app contains no ffmpeg helper. [FFmpegBackend.swift:14](/Users/henry/Desktop/clipx/Sources/ClipxExport/FFmpegBackend.swift:14) falls back to Homebrew locations, masking the omission on a development Mac. Supplying the static binary mentioned in the README is insufficient without copying it into the app and checking its presence during packaging.

**C09 · P2 — The MAS target exposes network features without network entitlements.** [project.yml:96](/Users/henry/Desktop/clipx/project.yml:96) and [Clipx-MAS.entitlements](/Users/henry/Desktop/clipx/Configs/Clipx-MAS.entitlements) omit both incoming and outgoing network entitlements, but Remote and Stint remain in its source/settings. A signed sandboxed app cannot initiate those connections/listeners under the declared permissions. This follows from the configuration and [Apple's network entitlement contract](https://developer.apple.com/library/archive/documentation/Miscellaneous/Reference/EntitlementKeyReference/Chapters/EnablingAppSandbox.html); the unsigned build does not validate it. The variant must either provide those capabilities or consistently exclude their flows.

## Native UI and application behavior findings

**N01 · P1 — Rapid source switching crashes the player.** [PlayerController.swift:63](/Users/henry/Desktop/clipx/Sources/ClipxPlayer/PlayerController.swift:63) starts an unowned metadata task. After loading A then B, A can complete and call [installPeriodicObserver at line 275](/Users/henry/Desktop/clipx/Sources/ClipxPlayer/PlayerController.swift:275) with B's observer token. Compiling the unchanged controller and calling `load` twice reproduced `SIGABRT`: “An instance of AVPlayer cannot remove a time observer that was added by a different instance of AVPlayer.” Stale loads must not publish, and each token must remain paired with its owning player through teardown.

**N02 · P1 — A bad Remote port can cause a launch crash loop.** [SettingsView.swift:398](/Users/henry/Desktop/clipx/Sources/ClipxApp/SettingsView.swift:398) persists an unrestricted integer; [AppEnvironment.swift:139](/Users/henry/Desktop/clipx/Sources/ClipxApp/AppEnvironment.swift:139) converts it with `UInt16(...)` before its error handler. Values such as -1 or 65536 trap, which an isolated conversion probe confirmed. Enabling Remote saves the enabled state, and bootstrap repeats the same conversion on the next launch. Validate both input and persisted configuration, with a recoverable fallback for invalid stored values.

**N03 · P2 — Changing selection discards inspector drafts.** Names save only through [onSubmit at InspectorView.swift:93](/Users/henry/Desktop/clipx/Sources/ClipxLibrary/InspectorView.swift:93); notes wait 600 ms, but [onDisappear at line 63](/Users/henry/Desktop/clipx/Sources/ClipxLibrary/InspectorView.swift:63) cancels their write without flushing it. RootView recreates the inspector for each selected clip. Editing a name and clicking another clip without Enter, or leaving soon after typing notes, therefore loses the draft. This is established by view lifecycle/control flow; no GUI automation was run. Commit/flush behavior must cover navigation and retain drafts when persistence fails.

**N04 · P2 — Delete/Undo does not restore the deleted clip.** [ClipGridView.swift:132](/Users/henry/Desktop/clipx/Sources/ClipxLibrary/ClipGridView.swift:132) snapshots some relationships, deletes the clip, and recreates a new ID through `saveRange`. It omits collections, purpose, original creation time, used count, and review linkage; export foreign keys were already set to NULL. Undo can thus return a clip outside its former groups with lost history. The omissions are explicit in the restoration code and schema. A complete snapshot/restore operation should preserve the identity and relationships promised by Undo.

**N05 · P2 — Structured attributes cannot be cleared.** [InspectorView.swift:224](/Users/henry/Desktop/clipx/Sources/ClipxLibrary/InspectorView.swift:224) passes nil when deselecting shot type, camera movement, or setting. [MarkerStore.swift:93](/Users/henry/Desktop/clipx/Sources/ClipxPlayer/MarkerStore.swift:93) interprets nil as “do not update.” An actual-store probe assigned “wide,” cleared it, and fetched “wide” again. The update boundary needs to distinguish “unchanged” from “set NULL”; otherwise the display lies until it reloads.

**N06 · P2 — Project-wide bridge exports use the previous selection.** [ProjectHeaderView.swift:158](/Users/henry/Desktop/clipx/Sources/ClipxLibrary/ProjectHeaderView.swift:158) starts asynchronous project selection, then immediately starts FCPXML/Obsidian export, whose task reads the current global selection. With no prior selection it can report no clips; with another selection it can export the wrong clips. The video path correctly awaits selection at line 180. This is a source-level ordering defect. Passing explicit project clip IDs would also avoid changing global selection to initiate an export.

**N07 · P2 — Calendar hides valid saved-clip matches.** [LibraryView.swift:67](/Users/henry/Desktop/clipx/Sources/ClipxLibrary/LibraryView.swift:67) gives Calendar only sources, while [its source query at line 184](/Users/henry/Desktop/clipx/Sources/ClipxLibrary/LibraryView.swift:184) excludes every source for clip-attribute filters. A matching clips array exists but is never rendered. In the default calendar, rating/attribute filters or a clip-name/tag search can show “No footage” despite valid matches. Sidebar shortcuts switch to grid, which covers some entry points; toolbar search and FilterSidebar do not. The view-mode result contract must account for both source and clip matches.

**N08 · P2 — Date/availability filters differ for clips and sources.** [SearchEngine.search](/Users/henry/Desktop/clipx/Sources/ClipxTagging/SearchEngine.swift:46) ignores `dateFrom`, `dateTo`, and `onlineOnly`; an actual-method probe returned an offline clip outside the requested dates. [Recently Imported](/Users/henry/Desktop/clipx/Sources/ClipxLibrary/SidebarView.swift:136) sets a seven-day date filter, but [the source query](/Users/henry/Desktop/clipx/Sources/ClipxLibrary/LibraryView.swift:175) applies it to recording time when available. Footage filmed last year and imported today is therefore missing, while old saved clips remain. Import time, recording time, and clip creation time need explicit query semantics across result types.

**N09 · P2 — Playback remains “playing” at EOF and the button cannot restart it.** [PlayerController.swift:147](/Users/henry/Desktop/clipx/Sources/ClipxPlayer/PlayerController.swift:147) changes a Boolean on button intent but does not observe completion or seek before replay. The unchanged-controller probe ended with `isPlaying=true`, actual rate 0, and playhead at duration. The first click only set the Boolean false; the second left it true at rate 0. A completion transition and replay position must be part of the playback state machine.

**N10 · P2 — Tag and note edits leave search results stale.** [TagStore.swift:36](/Users/henry/Desktop/clipx/Sources/ClipxTagging/TagStore.swift:36) and [Inspector notes commits](/Users/henry/Desktop/clipx/Sources/ClipxLibrary/InspectorView.swift:287) do not bump `libraryRevision`, while [LibraryView](/Users/henry/Desktop/clipx/Sources/ClipxLibrary/LibraryView.swift:34) relies on that signal to reload. Removing a searched-for tag updates the inspector but leaves the clip in search until another refresh. Notes likewise affect FTS results without refreshing their UI snapshot. This is a missing-invalidation path, not a demonstrated SQL injection or indexing failure.

## Server, export, and bridge behavior findings

**B01 · P1 when Remote is enabled — Unauthenticated requests can crash the whole app.** [HTTPRequest.swift:45](/Users/henry/Desktop/clipx/Sources/ClipxServer/HTTPRequest.swift:45) indexes an empty query split for `GET /?=`, and [line 65](/Users/henry/Desktop/clipx/Sources/ClipxServer/HTTPRequest.swift:65) accepts negative Content-Length before constructing a reversed range. Both requests produced SIGTRAP against the unchanged parser. [HTTPServer.swift:75](/Users/henry/Desktop/clipx/Sources/ClipxServer/HTTPServer.swift:75) parses before pairing/Host validation, so a reachable network client needs no PIN. Reject malformed framing and query components before indexing or arithmetic; distinguish malformed input from an incomplete request.

**B02 · P1 — Changing playback speed exports the wrong cut.** [FFmpegBackend.swift:44](/Users/henry/Desktop/clipx/Sources/ClipxExport/FFmpegBackend.swift:44) retimes video/audio but keeps output `-t` equal to the unscaled source range; output-side seek also interacts with the altered timeline. Actual exports of marks 2–6 seconds from a 12-second synthetic source lasted **4 seconds at both 2× and 0.5×**, instead of 2 and 8 seconds. Faster rendering consumes content beyond Out; slower rendering truncates the selection. Stint uses the same renderer. Trim a defined source-time interval before retiming and validate both boundary frames and output duration.

**B03 · P1 for the FCP bridge — The declared FCPXML version and asset structure disagree.** [FCPXMLWriter.swift:81](/Users/henry/Desktop/clipx/Sources/ClipxBridges/FCPXMLWriter.swift:81) emits self-closing `asset` elements with `src`, then declares version 1.13. [Apple documents the transition to media-rep in 1.9](https://developer.apple.com/documentation/professional-video-applications/media-rep), and its [published 1.10 DTD](https://developer.apple.com/documentation/professional-video-applications/document-type-definition) requires `media-rep+` children on assets and has no `asset@src`. A generated fixture uses the earlier structure. The incompatibility follows from that documented schema transition; no Final Cut import or packaged 1.13 DTD validation was performed. This is separate from the README's acknowledged lack of rich metadata.

**B04 · P1 — Same-name Obsidian clips overwrite and misassociate notes.** [ObsidianWriter.swift:36](/Users/henry/Desktop/clipx/Sources/ClipxBridges/ObsidianWriter.swift:36) identifies a sidecar solely by sanitized display name. Two distinct “Same name” clips wrote one `Same name.md`; the final fixture contained clip 2's ID and clip 1's personal notes. Sanitization/case collisions have the same effect. Use stable identity in the filename/metadata and verify identity before merging existing user text.

**B05 · P1 — Cancellation can be lost, and restarting the queue races old cleanup.** [CancellerBox.swift:15](/Users/henry/Desktop/clipx/Sources/ClipxExport/CancellerBox.swift:15) does not remember cancellation before registration. The exact box/backend probe canceled first, yet ffmpeg exited successfully and wrote the output. [ExportPipeline.cancelAll](/Users/henry/Desktop/clipx/Sources/ClipxExport/ExportPipeline.swift:42) also sets the worker idle before its task finishes; immediate enqueue starts another worker sharing its cancellation/state fields. The latter race is established by control flow rather than GUI reproduction. Cancellation and cleanup must belong to a particular job/worker generation, and idle must mean that worker has drained.

**B06 · P1 — Refreshing Stint comments deletes subsequent user notes.** [StintBridge.swift:338](/Users/henry/Desktop/clipx/Sources/ClipxBridges/StintBridge.swift:338) replaces everything from the first review marker through the end of the note. A user paragraph appended after imported comments disappeared in an exact-method fixture. Keep generated review text separately, or delimit both ends of its region while preserving surrounding text; existing unbounded blocks need an explicit preservation rule.

**B07 · P1 with a deliberately malformed paired-client write — Invalid ranges can persist and crash later readers.** [ClipxRoutes.swift:456](/Users/henry/Desktop/clipx/Sources/ClipxServer/ClipxRoutes.swift:456) accepts arbitrary Int64 marks; [MarkerStore.saveRange](/Users/henry/Desktop/clipx/Sources/ClipxPlayer/MarkerStore.swift:15) checks only `out > in`. Negative and beyond-EOF ranges are accepted, including minimum/maximum Int64 bounds that overflow [Clip.durationMs](/Users/henry/Desktop/clipx/Sources/ClipxCore/Models/Clip.swift:85). The write/read path and overflow are established; no live user database was poisoned. Enforce valid source-time bounds at the shared write boundary and make read arithmetic defensive against preexisting invalid rows.

**B08 · P2 — HTTP ranges bypass the response cap, mishandle suffixes, and can overflow.** [Security.swift:121](/Users/henry/Desktop/clipx/Sources/ClipxServer/Security.swift:121) limits open-ended ranges only. The exact helper accepted a 100 MB explicit range despite its 1 MiB limit; [ClipxRoutes.swift:409](/Users/henry/Desktop/clipx/Sources/ClipxServer/ClipxRoutes.swift:409) reads that range into memory. `bytes=-500` returned the first 501 bytes instead of the last 500, and an Int64.max open-ended start trapped. These file routes require pairing. Parse valid range forms with checked arithmetic and bound or stream every accepted response, not only the default form.

**B09 · P2 — Drag export ignores saved rotation and speed.** [ClipTransferable.swift:46](/Users/henry/Desktop/clipx/Sources/ClipxBridges/ClipTransferable.swift:46) calls either backend without those source values, leaving defaults of 0°/1×. Menu export and review rendering supply them. A transformed clip dragged to another app therefore produces different media from its normal export. The inconsistency is explicit at the call sites and should disappear behind a shared render operation.

**B10 · P2 — FCPXML can turn a one-frame selection into zero frames.** [FCPXMLWriter.swift:71](/Users/henry/Desktop/clipx/Sources/ClipxBridges/FCPXMLWriter.swift:71) floors `seconds * fps`, although the app stores frame boundaries rounded to milliseconds. A 30 fps fixture with a 33 ms mark generated `0/30s`; a one-frame clip generated zero duration. This affects constant-frame-rate footage and is separate from the known VFR approximation. Recover nearest frame indices, derive duration from endpoints, and accumulate timeline offsets in a consistent sequence timebase.

**B11 · P2 — Export progress is not properly observed.** [ExportProgressView.swift:11](/Users/henry/Desktop/clipx/Sources/ClipxExport/ExportProgressView.swift:11) stores the ObservableObject pipeline in State, then uses an empty `onReceive(objectWillChange)` closure. That neither observes the object through ObservedObject nor changes view state, so later queue/progress updates do not independently invalidate the sheet. This is a code-level observation finding; no GUI run was used to count redraws. A view that observes the pipeline should own the changing queue content.

**B12 · P2 — Ordinary failures/cancellation leave export history “in progress.”** [ExportPipeline.swift:102](/Users/henry/Desktop/clipx/Sources/ClipxExport/ExportPipeline.swift:102) creates the history row and changes it only on success. [The catch path at line 164](/Users/henry/Desktop/clipx/Sources/ClipxExport/ExportPipeline.swift:164) removes partial output but never writes failed/cancelled status; launch-time reconciliation repairs it only next session. History duration is also the unscaled range, including successful retimed MAS exports. Every exit needs one terminal state and the actual rendered duration; startup reconciliation should cover process interruption.

**B13 · P2 — A partial Stint failure strands already-created work.** [StintBridge.swift:245](/Users/henry/Desktop/clipx/Sources/ClipxBridges/StintBridge.swift:245) creates the remote project and uploads sequentially, but stores credentials/mappings only after every upload succeeds. A later failure leaves earlier remote uploads without the local linkage required to resume or pull comments; retry creates another project. Temporary renders are also cleaned only after successful upload. This follows from the network/file/database ordering; no live API writes were made. Persist external identity and each committed step promptly, and register temporary-file cleanup on allocation.

**B14 · P2 — The phone player cannot be closed beneath its preparation/error overlay.** [WebContent.swift:185](/Users/henry/Desktop/clipx/Sources/ClipxServer/WebContent.swift:185) positions the overlay across the entire modal above the close header. Offline/preparing paths leave it present. Desktop Escape is available, but the phone's close control is covered. This is established from DOM/CSS and handlers, not a live phone session. Keep close/cancel reachable and give proxy failures a terminal state instead of repeated preparation.

**B15 · P2 — Clearing web search leaves stale results visible.** [WebContent.swift:527](/Users/henry/Desktop/clipx/Sources/ClipxServer/WebContent.swift:527) returns to Sources on empty input only if Sources is still the active tab. Entering search already clears that active class, so the condition cannot restore the prior pane. Older asynchronous searches can also overwrite newer results. Explicit pane/query ownership should determine clear behavior and reject obsolete completions.

**B16 · P2 — Remembered MAS destinations do not retain filesystem permission.** [ExportActions.swift:77](/Users/henry/Desktop/clipx/Sources/ClipxExport/ExportActions.swift:77) and [SettingsView.swift:295](/Users/henry/Desktop/clipx/Sources/ClipxApp/SettingsView.swift:295) keep export/vault paths as strings. They do not persist and activate scoped bookmarks as watched folders do. Access granted by choosing an external folder is therefore not retained across sandboxed launches; vault writes fail, and remembered export destinations can fail or require another picker. This is a source-and-platform-contract finding, not a signed MAS reproduction. [Apple documents durable sandbox file access](https://developer.apple.com/documentation/security/accessing-files-from-the-macos-app-sandbox).

| Proxy lifecycle | [WebProxyEngine.swift:49](/Users/henry/Desktop/clipx/Sources/ClipxServer/WebProxyEngine.swift:49) starts one transcode per hash with no global concurrency limit, cancellation API, or eviction. Failed jobs are reaped and retried by status polling. Resource exhaustion was not profiled. |
| Remote transforms | Proxy identity/input and the remote source DTO omit permanent rotation/speed. Remote playback therefore differs from native playback. Whether remote marking should follow source time or edited playback time needs an explicit product decision. |
| IPv6 | [Security.swift:33](/Users/henry/Desktop/clipx/Sources/ClipxServer/Security.swift:33) splits Host on the first colon, rejecting valid IPv6 literals such as `[::1]:7878`. The advertised IPv4 path remains usable. |
| Review refresh edges | An empty comment response preserves the old digest while setting its count to zero. Rendered-review duration metadata also clamps speed to 0.25 although custom native speeds can be lower. Nested comment-thread handling depends on Stint's actual contract. |
| Free-form sidecar sections | Obsidian note extraction treats a `## Linked` prefix as the generated-section boundary, so a user heading with that prefix can truncate preserved notes. Drag rendering also lacks cancellation/partial-file cleanup. |
| Browser task/cache lifetime | Old detail responses can populate a newer selection, failed sprite promises remain cached, blob URLs are not revoked, and previous-source proxy polling can outlive selection. These are source-supported races/leaks; no browser stress test was performed. |
| Color handling | FFmpeg stamps BT.709/8-bit output without explicit transfer/gamut conversion or HDR tone mapping. HDR/wide-gamut correctness requires dedicated fixtures; the successful SDR renders do not establish it. |
| Startup/scale | Integrity checking and backup run synchronously from bootstrap; several UI queries use detached tasks without request guards, and library loading replaces existing content with a spinner. Their cost/state disruption warrants real profiling, but this review assigns no measured latency or memory claim. |

Their presence makes focused repair plausible.

The README already acknowledges unfinished Sparkle distribution setup, static ffmpeg sourcing, samples/crash reporting, approximate VFR stepping, narrow FCP metadata, and deferred integrations. Those are not counted again as newly discovered defects. The missing helper copy phase and incompatible FCP schema are additional concrete problems that remain even after the documented prerequisites are supplied. The LAN server is opt-in and explicitly uses HTTP; the input-validation crashes are defects within that stated boundary.

The main open decision is how much of the current product to carry forward. The evidence supports stabilizing saved-work integrity and the find/mark/export loop; it does not establish that replacing SwiftUI, GRDB, or the whole application would be a better investment. A substantive implementation/refactor plan should follow that discussion.
